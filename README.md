# ui-kit

Общая дизайн-система систем Sumotori: токены, компоненты, JS-поведение, шрифт. Обновили версию в проекте — подтянулся новый внешний вид.

Стек потребителя: Tailwind CSS v4 (standalone), HTMX, Alpine.js. Сейчас ядро собрано на Tailwind **v4.3.3**.

## Состав

| Каталог                     | Что                                                                                  |
| --------------------------- | ------------------------------------------------------------------------------------ |
| `core/css/index.css`        | точка подключения ядра                                                               |
| `core/css/theme.css`        | токены: цвета, радиус, шрифт, палитра статусов. Редизайн начинается здесь            |
| `core/css/components/`      | внешний вид компонентов, один компонент — один файл                                  |
| `core/css/vendor/basecoat/` | структура и поведение компонентов [Basecoat](https://basecoatui.com), не правим      |
| `core/css/base.css`         | элементы без классов, хелперы HTMX и Alpine                                          |
| `core/js/ui-kit.js`         | общее поведение: CSRF для HTMX, тосты, тайм-аут сессии, Alpine-компоненты полей и списков |
| `core/js/layout.js`         | оболочка приложения: боковое меню, загрузчик страницы, Ctrl+Enter, «Назад»          |
| `core/js/validation.js`     | клиентская валидация форм по `data-rules`                                            |
| `core/js/`                  | Basecoat, HTMX, Alpine, графики, сканер QR и штрихкодов                              |
| `core/fonts/`               | Inter Variable                                                                       |
| `thymeleaf/templates/`      | фрагменты для Spring MVC + Thymeleaf                                                 |
| `catalog/`                  | каталог компонентов, образец разметки                                                |

## Подключение

CSS подключается исходниками в сборку Tailwind проекта, на выходе один файл:

```css
@import "tailwindcss";
@source "<шаблоны проекта>";
@source "<ui-kit>/thymeleaf/templates";
@import "<ui-kit>/core/css/index.css";
@import "./domain.css";
```

Второй `@source` нужен, потому что фрагменты адаптера используют утилиты Tailwind. Без него Tailwind их не увидит, если библиотека лежит вне дерева проекта. Проект на другом адаптере указывает его каталог.

Статику проект раздаёт сам: `core/js/` по адресу `/js/`, `core/fonts/` по адресу `/fonts/`.

Скрипты в `<head>`, все с `defer`, порядок важен: `basecoat.min.js`, `htmx.min.js`, `charts.js`, `ui-kit.js`, `alpine.min.js`. CSRF-токен — в `<meta name="_csrf">` и `<meta name="_csrf_header">`. `layout.js` подключается без `defer` в конце `<body>` страниц с оболочкой приложения: ему нужны `#sidebar` с `.sidebar-group-toggle`, `#sidebar-toggle`, `#sidebar-collapse-toggle` и `#sidebar-resize-handle`. Образец оболочки — `layouts/app.html` в sumotori-service. `validation.js` от оболочки не зависит: в конце `<body>` или в `<head>` с `defer` на страницах с формами.

## Thymeleaf

`thymeleaf/templates/components/` — фрагменты для Spring MVC + Thymeleaf. Каталог подключается к шаблонам проекта, вызов `~{components/<имя> :: <фрагмент>(...)}`.

Что фрагменты ждут от проекта:

- бин `money` с методом `format(BigDecimal)` — сумма для `bars`;
- бин `fieldRules` с методом `of(form, field)` — JSON правил валидации поля для `data-rules` или `null`;
- в модели страницы с `periodToolbar` и `periodPresets` — `filter` и `presets`: пресет умеет `label`, `fromParam()`, `toParam()`, `matches(filter)`;
- подписи статусов в `messages.properties`: `<kind>Status.<КОД>` или `status.<КОД>`.

`scannerDialog` подключается один раз в лэйауте, `viewer` — один на страницу, где есть файлы. Их поведение — в `core/js/ui-kit.js`.

`scanField(pick=true)` выбирает вариант по отсканированному коду: родитель — `x-data="scanPick('Код {code} не найден')"`, внутри `x-ref="target"` с комбобоксом, у вариантов `data-code`. Текст ошибки необязателен, после выбора вызывается `picked()`, если он есть.

## Каталог

`catalog/index.html` — все компоненты ядра на одной странице. Это образец разметки для любого адаптера: Thymeleaf, Go и т.п. Под каждым демо — вызов Thymeleaf-фрагмента.

```sh
bin/catalog            # собрать CSS каталога
bin/catalog --watch    # пересобирать при правках
```

Каталог работает без сервера, поэтому HTMX-демо в нём ничего не загружают. Новый компонент или вариант сначала добавляем в каталог, потом в адаптеры.

## Правила

- Ядро не знает о предметной области проектов: никаких статусов машин, адресов страниц, бизнес-терминов. Доменные компоненты и соответствие «статус → цвет» живут в проекте и собираются из компонентов ядра.
- Стиль задаётся только классом компонента и `data-*` атрибутами. Утилиты Tailwind на кнопках, полях и бейджах в проектах не вешаем.
- Тёмной темы нет.

## Версии

Теги `vX.Y.Z`, проект фиксирует версию у себя.

- **patch** — исправления без изменения разметки.
- **minor** — новые компоненты и варианты, внешний вид, токены. Разметка существующих компонентов не меняется.
- **major** — меняется разметка, классы или атрибуты существующих компонентов либо мажорная версия Tailwind. В описании релиза — что поменять в проектах.

## Действия и подсказки

`actions.js` и `input-suggestions.js` подключаются с `defer` после `ui-kit.js`, до Alpine. `components/actions :: actions` принимает необязательные фрагменты `primary`, `secondary`, `more`; пустые группы не передаются. Для заголовка доступны фрагменты `statusContent` и `metadataContent`. Меню «Ещё» использует нативный `details`, сохраняет обычные кнопки, ссылки и формы.

`uiKit.textSuggestions.attach(input, {load: (query, signal) => Promise<string[]>})` подключает подсказки свободного ввода. Источник данных, права доступа и адреса определяет приложение. Необязательные параметры: `delay` (200 мс), `maxLength` (200), `label`, `loadingLabel`. `refresh(input)` запускает поиск, `destroy(input)` снимает подключение и восстанавливает атрибуты. Список работает внутри диалога, отменяет устаревшие запросы и удаляется при замене HTMX-фрагмента. Пример есть в каталоге.

Проверки поведения компонентов без сторонних зависимостей: `node --test tests/*.test.cjs`. Node нужен только для этих проверок; сборка и использование библиотеки по-прежнему обходятся без него.

## Мобильный режим

`mobile.js` подключается с `defer` после `ui-kit.js`. Он подготавливает таблицы и навигацию после загрузки, `page:swapped` и HTMX, учитывает экранную клавиатуру и ограничивает всплывающие списки доступной областью. Изменения раскладки включаются до 768 px, размеры для касания также применяются к планшетам с `pointer: coarse`.

У простой таблицы `data-mobile="records"` превращает строки в мобильные записи после подготовки JS. Заголовки становятся подписями значений; `data-mobile-priority` на th выделяет главный показатель. Формы, ссылки и права остаются в исходной разметке. Для объединённых строк и многоуровневых заголовков нужен отдельный вариант.

`data-mobile="periods"` у матрицы с последней колонкой «Итого» добавляет выбор одного месяца. Режим «Все месяцы» возвращает сравнение. Без JavaScript остаётся исходная таблица. Демо мобильных записей есть в каталоге.

### Контекст и черновики

Подключение `core/js/workspace.js` включает восстановление прокрутки и локальных вкладок, а также черновики основных POST-форм с `.form-actions`. В `<head>` требуется `<meta name="ui-user" content="идентификатор пользователя">`. Хранение: sessionStorage, отдельно для пользователя, срок два часа. Если страница открылась после отправки формы, значит сервер ответил, и отправленный черновик удаляется. Прокрутка и вкладки восстанавливаются только при «Назад», «Вперёд» и перезагрузке. `page:swapped` передаёт это в `detail.fromHistory`. Файлы, пароли, служебные поля, формы в dialog и формы с hx-post не сохраняются. Восстановление выполняется кнопкой, повторной отправки POST нет.

Для собственного роутера: отправлять `workspace:before-navigation` перед заменой страницы, `page:swapped` после замены и `workspace:navigation-failed` с `detail.url` при сетевом сбое GET. `main[data-reset-context="true"]` отключает восстановление позиции, например при повторном вводе материалов. Выход через форму `/logout` очищает состояние пользователя.

### Фото и галерея

`core/js/photos.js` подключается до Alpine и до скриптов приложения. Он регистрирует `photoSlot` и `photoUploads`, предоставляет `whenAlpine`, проверку HEIC/HEIF, отправку файлов и повтор загрузки. Сжатие использует `compressPhoto` из `ui-kit.js`; к моменту начала загрузки оба скрипта должны быть загружены.

Приложение задаёт `uiPhotos.headers = function () { return {...}; }` для CSRF или другого механизма авторизации. Адрес передаётся через `target()`, а `track(promise)` позволяет приложению дождаться завершения загрузок перед отправкой формы. Multipart-поля — `photo` и необязательное `name`; ответ — `{url, name, deleteUrl}`. Другой протокол можно подключить заменой `uiPhotos.upload(url, file, name)`. Автоматического повтора POST нет.

Thymeleaf-фрагменты: `components/gallery :: photo(url, title, deleteUrl)` и `pending`. Если `deleteUrl` отсутствует, кнопка удаления не выводится. Кнопка отправляет всплывающее событие `photo:delete` с `detail.url`; подтверждение, права и выполнение удаления остаются приложению. Мобильные стили галереи включены в основной CSS. Демо загрузки находится в основном каталоге.

### Навигация и уведомления

`sidebar-navigation.js` подключается после разметки `#sidebar`. Он отмечает активную ссылку по `data-nav-paths` и сохраняет прокрутку меню. После разметки страницы подключаются `layout.js`, `validation.js` и, при необходимости, `navigation.js`:

```html
<script src="/js/navigation.js" data-ui-navigation
        data-navigation-exclude="/(files|logout|login|catalog)(/|$)|/export"></script>
```

Пути исключений задаёт приложение. Модуль обрабатывает только переходы GET того же сайта, выполняет предзагрузку, заменяет `main`, отправляет события для `workspace.js` и защищает изменённые POST-формы от случайного ухода. Формы с `data-save-url` или `data-navigation-ignore-dirty` отвечают за своё сохранение. Ссылки с download, onclick, target, HTMX или якорем сохраняют собственное поведение. Новые скрипты внутри main выполняются при замене страницы.

`toast.js` предоставляет `uiToast(data)` и обратный отсчёт у действия уведомления. Серверная привязка данных остаётся в приложении: `<script data-ui-toast>uiToast(data)</script>`. Навигация распознаёт этот атрибут при загрузке страницы. Нужен элемент `#toaster`, инициализированный Basecoat.

Все проверки JavaScript: `node --test tests/*.test.cjs`.
